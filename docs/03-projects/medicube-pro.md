# 메디큐브프로에서 본 운영의 복잡성

메디큐브프로는 여러 부서가 나눠 처리하던 인플루언서 운영, 정산, 보상, 물류 업무를 하나의 흐름으로 묶는 경험이었습니다. 기술적으로 어려운 부분도 있었지만, 더 어려웠던 것은 서로 다른 부서의 언어를 하나의 운영 구조로 맞추는 일이었습니다.

## 엑셀과 기억에 의존하던 일

SNS 캠페인 승인, 담당자 배분, 현금 지급, 제품 지급, 주소 검증, 관세 문서, 물류 상태는 서로 이어져 있었습니다. 하지만 수작업이 많으면 누가 무엇을 해야 하는지 흐려지고, 예외가 생겼을 때 다시 찾기 어려워집니다.

이 경험은 제가 운영 자동화를 단순한 편의 기능이 아니라 책임과 상태를 드러내는 구조로 보게 만들었습니다.

## 화면은 부서 간 합의의 결과물이다

기획, 디자인, 백엔드, 물류, 자금, 마케팅이 같은 화면을 두고 각자 다른 문제를 말했습니다. 화면 구조를 정리한다는 것은 단순히 화면을 만드는 것이 아니라, 서로 다른 업무 기준을 한곳에 맞추는 일이었습니다.

그래서 저는 개발 전에 실제 업무 흐름을 듣고, 상태와 예외를 먼저 나눠 보는 방식을 중요하게 생각하게 됐습니다.

## 내가 남기고 싶은 기준

사람이 기억해야 하는 규칙은 언젠가 빠집니다. 중요한 운영 흐름은 상태, 알림, 예외 조회, 변경 이력으로 남아야 합니다.

이 경험 이후로 저는 운영 시스템을 볼 때 "이 화면이 업무 합의를 대신 설명할 수 있는가", "사람이 실수했을 때 사고가 커지지 않는가"를 먼저 생각합니다.
