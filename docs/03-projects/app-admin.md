# 앱 관리자에서 본 운영자의 화면

앱 관리자는 외부 팀과 운영 조직이 앱 기능을 직접 관리하기 위한 화면이었습니다. 게시글, 이벤트, 상품, 푸시, 포인트 환불처럼 운영자가 매일 판단해야 하는 일이 모여 있었습니다.

## 운영자는 화면을 보고 결정한다

관리자 화면은 내부용이라 대충 만들어도 되는 화면이 아닙니다. 운영자는 그 화면을 보고 고객에게 답하고, 이벤트를 열고, 포인트를 조정하고, 상품을 관리합니다.

그래서 저는 관리자 화면에서 빈 상태, 미리보기, 오류 메시지, 확인 흐름, 컬럼 이름 같은 작은 요소를 중요하게 보게 됐습니다. 작은 정보 부족이 운영자의 잘못된 판단으로 이어질 수 있기 때문입니다.

## 작은 반복을 줄이는 일

아이콘 관리, 토스트, 모달, 표 생성처럼 작아 보이는 반복도 계속 쌓이면 팀의 속도를 늦춥니다. 이런 반복을 훅이나 유틸로 정리하면 다음 화면을 만들 때 더 중요한 운영 흐름에 집중할 수 있습니다.

이 경험은 제가 개발자 경험을 사용자 경험과 분리해서 보지 않게 만든 사례입니다. 만드는 사람이 덜 헷갈려야 사용하는 사람에게도 더 안정적인 화면이 나갑니다.
