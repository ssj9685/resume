# 통합 관리자 시스템에서 본 반복의 문제

통합 관리자 시스템은 여러 관리자 페이지가 각자 다른 구조로 자라나며 생긴 반복을 정리한 경험입니다. 비슷한 화면을 계속 만들고, 같은 버그를 프로젝트마다 다시 고치고, 권한과 라우팅 기준이 흩어지는 문제가 있었습니다.

## 반복은 단순한 귀찮음이 아니다

반복되는 테이블, 폼, 권한, 라우팅은 처음에는 빠르게 만드는 것처럼 보입니다. 하지만 시간이 지나면 팀이 같은 판단을 계속 반복하게 만들고, 리뷰도 구현 디테일에 묶이게 됩니다.

이 경험을 통해 저는 공통화가 코드 양을 줄이는 일이 아니라 팀의 판단 기준을 정리하는 일이라고 보게 됐습니다.

## 한 번에 바꾸지 않는 방식

운영 중인 관리자 시스템은 전면 교체가 늘 좋은 답은 아니었습니다. 이미 사용 중인 화면과 운영 흐름이 있었기 때문에, 공통화할 수 있는 부분부터 단계적으로 옮기는 방식이 더 현실적이었습니다.

이후에도 레거시를 볼 때 "새로 만들자"보다 "어떤 책임부터 안전하게 옮길 수 있는가"를 먼저 생각하게 됐습니다.

## 이 경험이 남긴 것

공통 플랫폼은 기술 구조이면서 동시에 협업 구조입니다. 메뉴, 권한, 라우팅, 테이블, 폼의 기준이 정리되면 새 화면을 만드는 사람도, 리뷰하는 사람도 같은 언어로 이야기할 수 있습니다.
