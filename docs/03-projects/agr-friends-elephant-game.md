# 웹뷰 게임에서 배운 실기기 감각

에이지알 프렌즈와 코끼리 게임은 웹뷰 안에서 게임을 만들며 실기기 문제를 깊게 본 경험입니다. 짧은 일정 안에서 게임을 출시해야 했고, 앱 개발자와 백엔드 개발자도 함께 참여할 수 있는 구조가 필요했습니다.

## 브라우저에서 되는 것과 앱에서 되는 것은 다르다

캔버스, 소리, 물리 엔진, 상태 관리, 앱과 웹의 연결이 함께 움직이니 브라우저에서 정상으로 보이는 것이 실기기에서는 다르게 동작했습니다. 특히 아이폰에서 발열과 멈춤이 발생했고, 웹뷰 검사 도구로 확인해 보니 캔버스와 소리 객체가 재진입마다 쌓이고 있었습니다.

이 문제를 겪으며 저는 "로컬에서 된다"는 말만으로는 충분하지 않다고 생각하게 됐습니다. 사용자가 실제로 만지는 환경에서 확인해야 합니다.

## 협업 가능한 구조의 중요성

짧은 일정에서는 혼자만 이해하는 구조가 위험합니다. 앱, 백엔드 개발자가 빠르게 참여할 수 있도록 역할을 나누고, 객체지향적인 구조와 명확한 책임 분리를 선택했습니다.

이 경험은 제가 구조를 짤 때 팀원의 진입 장벽을 같이 보게 만든 계기입니다. 좋은 구조는 똑똑해 보이는 구조가 아니라 여러 사람이 덜 헷갈리고 함께 움직일 수 있는 구조에 가깝습니다.

## 이 경험이 남긴 것

웹뷰 문제는 웹, 앱, 단말, 캐시, 배포 버전이 함께 얽힙니다. 저는 이 경험 이후로 문제를 재현할 때 실제 환경, 버전, 실행 흐름, 리소스 누적을 먼저 확인하려 합니다.
