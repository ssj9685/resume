# 기술을 깊게 들여다보려는 이유

저는 기술을 목록으로만 외우기보다 동작 원리를 직접 확인하는 편입니다. 앱과 웹의 경계, 실시간 통신, 상태 관리, 배포 문제를 다룰 때도 이 습관이 도움이 됐습니다.

## 네트워크와 프로토콜을 직접 만져본 경험

학부와 대학원 시절 네트워크와 프로토콜 관련 주제를 집중적으로 학습했고, 여러 개인 작업을 통해 이론을 실제 구현으로 연결했습니다.

### MQTT·Kafka 엣지 플랫폼 연구

대학원에서는 스마트팜 센서 데이터를 MQTT로 수집하고 Kafka·MongoDB·ThingsBoard로 연결하는 엣지 컴퓨팅 플랫폼 연구에 제1저자로 참여했습니다. 이 연구를 통해 제한된 장치와 네트워크 환경에서 수집, 전달, 저장, 시각화를 하나의 데이터 흐름으로 보는 기반을 쌓았습니다.

- [논문: Implementation of Edge Computing Platform for Smart Farm using MQTT and Kafka](https://drive.google.com/file/d/1zrVSHyFt8RN0O-QTKTSirF_ubP29TAo4/view?usp=sharing)

### 비디오 스트리밍

C 언어를 사용해 스트림에서 이미지를 캡처하는 프로젝트를 수행했습니다. 스트리밍 데이터 처리와 저수준 동작 원리를 직접 다뤄보며, 화면에 보이는 결과 뒤에 있는 데이터 흐름을 이해하는 데 관심을 갖게 됐습니다.

### WebSocket

Node.js로 WebSocket 프로토콜을 직접 구현했습니다. 외부 라이브러리를 쓰기 전에 핸드셰이크와 메시지 프레임이 어떻게 동작하는지 확인하면서, 실시간 통신을 추상화 뒤에 숨기지 않고 이해하려 했습니다.

### WebRTC

STUN과 TURN 서버를 직접 설정하고 네트워크 환경에 따른 연결 차이를 실습했습니다. 이 경험은 이후 앱 웹뷰, 딥링크, 실기기 환경 문제를 볼 때 브라우저 안에서만 답을 찾지 않는 습관으로 이어졌습니다.

## 상태 관리와 라이브러리 구조

Zustand가 React Context API와 달리 필요한 부분만 선택적으로 렌더링하는 구조에 관심을 가졌고, `useSyncExternalStore`와 selector 동작을 직접 확인했습니다.

이후 Class, `useSyncExternalStore`, 얕은 비교, Proxy를 결합해 비슷한 동작을 구현하며 전역 상태 선언의 보일러플레이트를 줄이는 실험을 했습니다. 이 경험은 `@ga-ut` 계열 오픈소스 작업과 개인 프로젝트로 이어졌습니다.

## 기술 독서

`헤드 퍼스트 디자인 패턴`을 다시 읽으며 현업에서 겪은 문제와 패턴의 쓰임을 연결해 봤습니다. 특정 패턴을 외우는 것보다, 언제 추상화가 도움이 되고 언제 오히려 읽기 어렵게 만드는지 판단하는 데 관심이 있습니다.

## Web3 구조 이해

대학원 시절 이더리움 구조, EVM, 트랜잭션, 가스, JSON-RPC 흐름을 정리하고 스마트 컨트랙트 개발을 경험했습니다. 실무의 중심 경험은 아니지만, 새로운 기술도 사용자 경험과 시스템 경계의 관점에서 이해하려는 배경이 됐습니다.
